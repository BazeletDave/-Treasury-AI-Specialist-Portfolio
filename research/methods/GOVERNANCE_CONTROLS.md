# Institutional AI Governance Control Matrix

| Control domain | Minimum evidence | Responsible decision |
| --- | --- | --- |
| Purpose and scope | Documented use case, excluded uses | Institutional owner |
| Identity and access | Role definitions, least privilege, credential lifecycle | Security owner |
| Data governance | Classification, minimization, retention and approved flows | Data steward |
| Model and tool provenance | Versions, dependencies, vendor and supply chain review | Technical owner |
| Delegated authority | Explicit actions allowed, approval gates, revocation | Accountable official |
| Output validation | Test sets, error rates, adversarial and regression tests | Independent reviewer |
| Monitoring | Logs, incident response, drift and change management | Operations owner |
| Contestability | Explanation, appeal and correction channels | Process owner |
| Procurement and integration | Security review, contractual obligations, applicable authorization | Acquisition and security |
| Accountability | Named owner, audit and remediation process | Institutional leadership |

This matrix is a research instrument, not an attestation of compliance or federal authorization. Tailor it to actual applicable requirements before deployment.
